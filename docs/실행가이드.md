# Docker 실행 가이드

처음부터 끝까지, 순서대로.

---

## 0. 사전 준비

**Docker Desktop**만 있으면 됩니다. Python이나 Node를 따로 깔 필요 없습니다.

```bash
docker --version          # Docker version 24.x 이상
docker compose version    # Docker Compose version v2.x 이상
```

> `docker-compose`(하이픈)가 아니라 `docker compose`(공백)입니다. v2부터 하위 명령으로 바뀌었습니다.

## 2. 환경 설정

```bash
cp .env.example .env
```

`.env`를 열어 **`LLM_BASE_URL`만** 상황에 맞게 고치면 됩니다. 나머지는 기본값으로 둬도 됩니다.

| 상황 | `LLM_BASE_URL` | 추가 설정 |
|---|---|---|
| **Claude Code 구독을 쓴다** ⭐ | `http://host.docker.internal:8787/v1` | 없음 — `run.bat claude` 가 알아서 |
| **compose가 모델까지 띄운다** | `http://llm:8000/v1` | `HF_HOME_HOST` — 아래 2-1 참고 |
| **LLM 없이 쓴다** | 아무거나 둬도 됨 | 없음 — 룰셋만 동작 |
| **호스트 Ollama** | `http://host.docker.internal:11434/v1` | `LLM_MODEL=qwen2.5:7b` |
| **호스트 vLLM** | `http://host.docker.internal:8000/v1` | `LLM_MODEL`을 서빙 중인 모델명으로 |
| **OpenAI** | `https://api.openai.com/v1` | `LLM_MODEL=gpt-4o-mini`, `LLM_API_KEY=sk-...` |

> **`localhost`가 아니라 `host.docker.internal`입니다.** 컨테이너 안에서 `localhost`는 컨테이너 자기 자신이라, 호스트에서 도는 Ollama·vLLM에 닿지 않습니다. 반대로 compose가 띄운 `llm` 서비스를 쓸 때는 서비스 이름 그대로 **`llm`**입니다.

### 2-0. Claude Code 구독으로 돌리기 (가장 쉬움)

GPU도, 모델 다운로드도, WSL2 UVA 문제도 없습니다. 이미 로그인해 둔 Claude Code를 그대로 씁니다.

```bat
run.bat claude
```

이 한 줄이 하는 일:

1. `claude --version` 이 되는지 확인
2. `bridge/claude_bridge.py` 를 **새 창**에 띄웁니다 (포트 8787)
3. `LLM_BASE_URL` · `VLM_BASE_URL` 을 그 다리로 맞춰서 compose를 올립니다
4. `llm` · `vlm` 컨테이너는 아예 띄우지 않습니다

`.env`는 건드리지 않습니다 — compose가 `.env`보다 셸 환경변수를 우선하기 때문입니다.

**다리가 하는 일.** api 컨테이너는 OpenAI 호환 `/v1/chat/completions` 하나만 압니다. Claude Code CLI는 HTTP 서버가 아니라 `claude -p` 로 한 번 돌고 끝나는 명령이라, 그 사이를 메우는 표준 라이브러리 한 파일입니다. 호스트에 pip로 아무것도 깔지 않습니다.

**이미지 판정도 같은 다리로 갑니다.** `vlm` 컨테이너가 필요 없습니다. 이미지는 요청 전용 임시 폴더에 풀린 뒤 Claude가 `Read` 로 열어 봅니다.

**주의 두 가지.**

- 다리 창을 닫으면 LLM이 멈춥니다. 룰셋과 OCR은 그대로 돕니다.
- 다리는 컨테이너가 닿아야 해서 `0.0.0.0` 에 붙습니다 — 같은 네트워크의 다른 기기도 호출할 수 있다는 뜻입니다. 공용 와이파이라면 `CLAUDE_BRIDGE_TOKEN` 에 아무 문자열이나 넣고 `.env` 의 `LLM_API_KEY` 에 같은 값을 쓰세요.

**보안 설계.** 이 다리로 들어가는 프롬프트에는 **점검 대상 페이지의 본문**, 즉 남이 쓴 글이 그대로 실립니다. "앞의 지시를 무시하고 …를 읽어라" 가 들어올 수 있다는 뜻입니다. 그래서 텍스트 요청에는 도구를 **하나도** 열지 않고(`--max-turns 1`), 이미지 요청에만 `Read` 를 열되 작업 디렉터리를 그 요청 전용 임시 폴더로 못박습니다. 이미지는 `data:` URL만 받습니다 — http(s)를 넘기면 CLI가 그 주소를 직접 가져가 SSRF 가드를 우회하기 때문입니다. 마지막으로 api 쪽 근거 역검증이 남아 있어, 페이지에 없는 문장을 인용한 지적은 어차피 버려집니다.

### 2-1. 로컬 HuggingFace 캐시의 모델 그대로 쓰기

이미 받아둔 모델이 있으면 다시 내려받을 필요 없습니다. compose에 `llm` 프로필을 넣어놨습니다.

`.env`에서 **캐시 루트**만 지정합니다. `hub` 폴더가 아니라 **그 부모**입니다.

```bash
# F:\huggingface_cache\hub  에 모델이 있다면
HF_HOME_HOST=F:/huggingface_cache
LLM_BASE_URL=http://llm:8000/v1
LLM_MODEL=Qwen/Qwen2.5-7B-Instruct-AWQ
```

> 역슬래시(`\`)가 아니라 **슬래시(`/`)** 로 씁니다. compose의 볼륨 표기에서 `\`는 그대로 먹지 않습니다.

`LLM_MODEL`은 캐시 폴더 이름을 되돌린 값입니다. `models--Qwen--Qwen2.5-7B-Instruct-AWQ` → `Qwen/Qwen2.5-7B-Instruct-AWQ`.

`.env`의 `COMPOSE_PROFILES`에 `llm`이 이미 들어 있어서, 그대로 띄우면 됩니다.

```bash
docker compose up --build      # 또는 run.bat / ./run.sh
```

`HF_HUB_OFFLINE=1`이 기본이라 **캐시에 있는 모델만** 쓰고 네트워크로 받지 않습니다. 캐시에 없는 이름을 넣으면 그 자리에서 실패합니다 — 조용히 몇 GB를 받아가는 일은 없습니다.

**GPU가 필요합니다.** vLLM은 NVIDIA GPU 위에서 돕니다. Docker Desktop 설정에서 WSL2 백엔드 + GPU 지원이 켜져 있어야 합니다.

```bash
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
```

**Windows(WSL2)라면 `VLLM_WSL2_ENABLE_PIN_MEMORY=1`이 필요합니다.** compose에 기본으로 넣어놨습니다. 없으면 이렇게 죽습니다.

```
RuntimeError: UVA is not available
  vllm/v1/worker/gpu/buffer_utils.py, line 47, in __init__
RuntimeError: Engine core initialization failed.
```

vLLM의 Model Runner V2는 UVA(통합 가상 주소)를 쓰는데, WSL2는 pinned memory가 **기본 비활성**이라 UVA가 잡히지 않습니다. vLLM 소스의 설명 그대로입니다 — 커널 4.19.121 이상이면 지원되지만 약간의 성능 저하 때문에 꺼져 있고, UVA가 필요하면 켜라는 플래그입니다.

플래그를 켜도 같은 오류가 나면 V1 러너로 내려가면 됩니다.

```bash
# PowerShell
$env:VLLM_USE_V2_MODEL_RUNNER=0 ; docker compose up
```

compose에 값 없이 키만 적어놨기 때문에, 호스트에 지정하지 않으면 컨테이너로 전달되지 않고 vLLM 기본값이 그대로 쓰입니다.

이게 안 되면 `llm` 프로필은 못 씁니다. 대신 호스트에 이미 깔린 **Ollama**를 쓰거나(`http://host.docker.internal:11434/v1`), `use_llm: false`로 룰셋만 돌리면 됩니다.

VRAM이 모자라면 더 작은 걸로 바꾸세요. 예: `LGAI-EXAONE/EXAONE-3.5-2.4B-Instruct-AWQ`, `Qwen/Qwen3-4B-AWQ`. 컨텍스트도 같이 줄이면 됩니다 — `LLM_MAX_MODEL_LEN=4096`.

### 2-2. 이미지 점검

**① 이미지 속 문구 읽기 — 별도 설정 없이 켜져 있습니다.** 페이지의 배너를 내려받아 글자를 읽고, 본문과 똑같은 룰을 적용합니다.

읽는 엔진은 **PaddleOCR 한국어 모델(`korean_PP-OCRv4_rec`)** 이 기본입니다. 모델은 이미지를 빌드할 때 함께 받아 두므로 첫 실행에서 따로 내려받지 않습니다. PaddleOCR을 못 쓰는 환경이면 컨테이너에 함께 들어 있는 tesseract로 조용히 내려갑니다.

무엇이 실제로 읽었는지는 두 곳에서 확인합니다.

```bash
curl -s localhost:8080/healthz
# {"ok":true, ..., "ocr_engine_requested":"auto", "ocr_engine_active":"paddle", "ocr_note":""}
```

결과 화면의 "이미지에서 읽은 문구" 상자에도 `읽은 엔진: PaddleOCR 한국어 모델`이 함께 나옵니다.

엔진을 고정하거나 빼려면 `.env`에서:

```dotenv
OCR_ENGINE=auto        # paddle 있으면 그것, 없으면 tesseract (기본)
OCR_ENGINE=paddle      # PaddleOCR만 쓴다. 없으면 이미지 점검을 실패로 남긴다
OCR_ENGINE=tesseract   # 예전 동작
WITH_PADDLE=0          # 빌드에서 아예 뺀다 (이미지 ~1.5GB 감소)
```

`WITH_PADDLE`은 **빌드 타임** 값이라, 바꾼 뒤에는 `docker compose up --build`로 다시 빌드해야 반영됩니다.

끄고 싶으면 요청에 `check_images: false`를 주면 됩니다.

```bash
curl -X POST localhost:8080/v1/check -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com","check_images":true,"use_llm":false}'
```

응답의 `stats`로 몇 장을 봤는지 확인할 수 있습니다.

```json
"stats": { "images_found": 12, "images_fetched": 5, "images_with_text": 3, "ocr_chars": 214 }
```

`images_found`보다 `images_fetched`가 적은 건 정상입니다. 아이콘·추적 픽셀(3KB 미만, 한 변 150px 미만)은 읽을 글자가 없어 건너뜁니다. 상한은 `.env`의 `MAX_IMAGES`(기본 8)입니다.

**② 이미지 자체 판정 — 멀티모달 모델이 필요합니다.** 비포·애프터 사진처럼 글자가 없는 문제를 봅니다. `.env`에 엔드포인트를 넣고, 요청에 `use_vlm: true`를 줘야 동작합니다.

```bash
VLM_BASE_URL=http://vlm:8000/v1
VLM_MODEL=Qwen/Qwen2.5-VL-3B-Instruct
VLM_SERVE_MODEL=Qwen/Qwen2.5-VL-3B-Instruct
```

`.env`의 `COMPOSE_PROFILES`도 함께 바꿉니다.

```dotenv
COMPOSE_PROFILES=llm,vlm
```

```bash
docker compose up --build      # 또는 run.bat llm,vlm
```

**GPU를 llm과 나눠 씁니다.** 기본값이 `VLM_GPU_UTIL=0.30`, `LLM_GPU_UTIL=0.90`인데 **합이 1을 넘습니다.** 둘을 같이 띄울 거면 `.env`에서 `LLM_GPU_UTIL=0.60` 정도로 낮추세요. 안 그러면 나중에 뜨는 쪽이 VRAM 부족으로 죽습니다.

`VLM_SERVE_MODEL`은 **캐시에 실제로 있는 이름**이어야 합니다. `HF_HUB_OFFLINE=1`이라 없으면 그 자리에서 실패합니다. 캐시 목록은 `F:\huggingface_cache\hub`의 폴더 이름을 되돌려 확인하세요.

`VLM_BASE_URL`을 비워두면 이 단계만 조용히 빠지고, 이유가 `llm_note`에 적힙니다.

## 3. 빌드하고 실행

### 한 줄로

**Windows — `run.bat` 을 더블클릭**하거나 터미널에서:

```bat
run.bat
```

macOS · Linux:

```bash
./run.sh
```

Docker가 켜져 있는지 확인 → `.env` 없으면 생성 → 빌드 → 기동 → API가 응답할 때까지 대기 → 브라우저 열기 → 로그 표시. 여기까지 자동입니다.

프로필을 인자로 바꿀 수 있습니다.

```bat
run.bat claude      :: Claude Code 구독으로 (GPU 불필요, 이미지 판정 포함)
run.bat none        :: 룰셋 + OCR 만 (GPU 불필요)
run.bat llm         :: 기본값 — 로컬 vLLM
run.bat llm,vlm     :: 로컬 vLLM + 이미지 자체 판정
```

### 직접 돌리기

```bash
docker compose up --build
```

**`--profile`을 붙이지 않아도 됩니다.** `.env`의 `COMPOSE_PROFILES`가 그 역할을 합니다.

```dotenv
COMPOSE_PROFILES=llm       # 비움 / llm / llm,vlm
```

바꾸고 싶은 게 그때 한 번뿐이라면 환경변수로 덮어쓰면 됩니다.

```bash
COMPOSE_PROFILES=llm,vlm docker compose up --build     # bash
$env:COMPOSE_PROFILES="llm,vlm"; docker compose up --build   # PowerShell
```

처음 한 번은 이미지를 만드느라 **3~6분** 걸립니다(OCR 설치 포함). 두 번째부터는 캐시가 있어 훨씬 빠릅니다.

이런 로그가 나오면 준비된 겁니다.

```
api-1  | INFO:     Uvicorn running on http://0.0.0.0:8080
web-1  | ▲ Next.js 14.2.5
web-1  | - Local:  http://localhost:3000
```

**`web`은 `api`가 healthy가 될 때까지 기다렸다 뜹니다.** compose에 `depends_on: condition: service_healthy`를 걸어놨기 때문에, api가 아직 준비 중이면 web이 잠시 대기합니다. 멈춘 게 아닙니다.

### 백그라운드로 돌리려면

```bash
docker compose up --build -d      # 분리 모드
docker compose logs -f            # 로그 따라 보기
```


## 5. 자주 쓰는 명령

```bash
docker compose ps                 # 상태 보기

docker compose restart api        # api만 재시작
docker compose down               # 중지 + 컨테이너 삭제
docker compose down -v            # 볼륨까지 삭제
docker compose up --build         # 코드 고친 뒤 재빌드
```

코드를 수정했다면 **`--build`를 꼭 붙이세요.** 안 붙이면 예전 이미지가 그대로 뜹니다.

## 6. 막힐 때

### 포트가 이미 쓰이고 있다

```
Error: bind: address already in use
```

3000이나 8080을 다른 게 쓰고 있습니다. `docker-compose.yml`에서 **왼쪽** 숫자만 바꾸세요.

```yaml
ports:
  - "3100:3000"     # 호스트 3100 → 컨테이너 3000
```

바꿨다면 `.env`의 `NEXT_PUBLIC_API_URL`도 같이 맞춰야 합니다.

### LLM에 연결이 안 된다

```json
{ "llm_used": false, "llm_note": "LLM 서버에 연결할 수 없습니다 (http://...)" }
```

**정상 동작입니다.** 룰셋 결과는 그대로 나오고, LLM 부분만 빠집니다. 조용히 실패하지 않고 이유를 알려 줍니다.

`llm_note`를 먼저 읽으세요. 실패 원인마다 문구가 다릅니다.

| `llm_note` | 뜻 | 할 일 |
|---|---|---|
| 연결할 수 없습니다 | 주소에 아무도 없음 | 아래 1~4번 |
| 응답 오류 404 | 서버는 살아 있는데 **모델명이 다름** | `/v1/models`와 `LLM_MODEL` 대조 |
| 응답 오류 400 | 요청 거부 (컨텍스트 초과 등) | `LLM_MAX_MODEL_LEN` 확인 |
| 시간 초과 | 첫 요청이 느림 | `LLM_TIMEOUT` 상향 |
| 빈 응답 | 모델이 content를 안 채움 | 다른 모델로 교체 |

순서대로 확인하세요.

```bash
# 1. 컨테이너가 살아 있는가 — llm이 목록에 없으면 COMPOSE_PROFILES에 llm이 없는 것
docker compose ps

# 2. vLLM이 실제로 준비됐는가 (모델 로딩에 1~3분 걸립니다)
docker compose logs llm | tail -20
curl http://localhost:8000/v1/models

# 3. 모델명이 정확히 일치하는가 — api가 보내는 이름과 서버가 아는 이름
curl localhost:8080/healthz

# 4. api 컨테이너 안에서 llm이 보이는가
docker compose exec api python -c "import httpx;print(httpx.get('http://llm:8000/v1/models').status_code)"
```

`3`에서 나온 `llm_model`과 `2`의 목록에 있는 `id`가 **글자 하나까지 같아야** 합니다. 다르면 404가 납니다.

`.env`를 고쳤으면 `docker compose up -d`로 다시 올려야 합니다 — **환경변수는 재시작해야 반영됩니다.**

호스트에서 도는 Ollama·vLLM에 붙일 때는 `localhost`가 아니라 `host.docker.internal`입니다. compose가 띄운 `llm` 서비스는 서비스 이름 그대로 `llm`입니다.

Linux에서 `host.docker.internal`이 안 잡히면 compose에 이미 넣어둔 아래 설정이 필요합니다(이미 들어 있습니다).

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

### 웹 화면에서 API 호출이 실패한다

브라우저 콘솔에 CORS 오류가 뜬다면 `.env`의 `CORS_ORIGINS`가 실제 접속 주소와 다른 경우입니다. 포트를 바꿨다면 여기도 맞춰 주세요.

```bash
CORS_ORIGINS=http://localhost:3100
```

### 컨테이너 이름이 이미 쓰이고 있다

```
Error response from daemon: Conflict. The container name
"/6ec96be92c2b_adpolicy-api" is already in use by container "339749b681e0..."
```

이전 실행이 깔끔하게 안 끝나서 컨테이너가 남은 경우입니다. 앞에 붙은 `6ec96be92c2b_`는 Docker가 예전 컨테이너를 밀어내며 붙인 접두사입니다.

```bash
docker compose down --remove-orphans
docker compose up --build -d --remove-orphans
```

그래도 남아 있으면 이름을 직접 지웁니다.

```bash
docker rm -f 339749b681e0        # 오류 메시지에 나온 ID
```

> compose에서 `container_name` 고정을 뺐기 때문에 지금 버전에서는 이 충돌이 잘 나지 않습니다. `run.bat`·`run.sh`도 실패하면 한 번 정리하고 자동으로 재시도합니다. 예전 버전으로 띄운 적이 있다면 위 명령으로 한 번 청소하세요.

### 빌드가 느리거나 실패한다

```bash
docker compose build --no-cache   # 캐시 무시하고 처음부터
docker system prune -a            # 안 쓰는 이미지 정리 (주의: 전부 지웁니다)
```

## 7. Docker 없이 돌리기

개발 중이라면 이쪽이 더 빠릅니다. 터미널 두 개가 필요합니다.

**터미널 1 — API**

```bash
cd api
pip install -e ".[dev]"
uvicorn adpolicy.main:app --reload --port 8080 --app-dir src
```

**터미널 2 — 웹**

```bash
cd web
npm install
npm run dev
```

테스트만 돌려볼 거라면 API 하나면 됩니다.

```bash
cd api && pip install -e ".[dev]" && pytest -q
# 753 passed
```

테스트는 **네트워크도 LLM도 필요 없습니다.**

정확도를 직접 재보고 싶다면 골든셋 하네스와 반려 복구 루프도 같은 자리에서 돕니다.

```bash
python -m adpolicy.evalkit --md eval/report.md   # 사전 점검 정확도
python -m adpolicy.ads     --md eval/recall.md   # 재현율 (픽스처 기준)
python -m adpolicy.mcp_server                    # MCP 서버 (stdio)
```
