# 코드 리뷰 반영 현황

> 원본: `개선사항.md` (2026-09-11 리뷰) · 반영 확인일: 2026-09-11
>
> **주의** — 원본 리뷰는 테스트 89건 시점의 스냅샷을 대상으로 했다. 그 사이 이 저장소는
> 543건까지 왔고, 지적 중 상당수는 이미 고쳐져 있었다. 아래는 **현재 코드에 다시 대조한**
> 결과다. "이미 해결"로 적은 것은 전부 코드에서 직접 확인했다.

## A. 버그·보안

| 항목 | 상태 | 근거 |
|---|---|---|
| A-1 SSRF 리디렉션 우회 | **이미 해결** | `fetcher.safe_get()`이 홉마다 `assert_safe_url`을 다시 걸고 `follow_redirects=False`. 압축 폭탄도 스트리밍으로 상한에서 끊는다 (B-6 동시 해결) |
| A-2 CI가 push에서 안 돎 | **고침** | 브랜치가 `master`인데 워크플로는 `main`만 봤다 → `branches: [main, master]` |
| A-3 web 빌드·lockfile | **부분 해결 → 마저 고침** | Dockerfile은 이미 `npm ci` + lockfile. CI만 `npm install`이라 재현 가능한 빌드가 아니었다 → `npm ci` |
| A-4 UA 스니핑 오탐 | **고침** | `navigator.userAgent`를 **읽기만 하는** 코드는 지적하지 않는다. 같은 스크립트 블록 안에서 `location`·`innerHTML`로 내용을 바꿀 때만 분기로 본다 |
| A-5 DEST-MISMATCH www 오탐 | **고침** | netloc 직접 비교 → 등록 도메인(eTLD+1) 비교. 기준 함수를 `fetcher.registrable_domain`으로 옮겨 rules와 cloaking이 **같은 기준**을 쓴다 |
| A-6 봇에게만 빈 200 미탐 | **이미 해결** | `analyze_divergence`가 "다른 프로필은 긴데 봇만 짧다"를 별도 신호로 처리 |
| A-7 봇 일시 실패 → 즉시 block | **고침** | 봇만 실패하면 1회 재시도. 타임아웃은 `warn`(불확실), 4xx는 `block`(명시적 거부)로 구분 |

## B. 정확도·성능

| 항목 | 상태 | 근거 |
|---|---|---|
| B-1 robots 파서 한계 | **고침** | 경로 단위 `Disallow: /landing` 판정, 그룹형 User-agent 레코드 처리, 더 긴 `Allow` 우선. googlebot 제거는 이미 되어 있었다 |
| B-2 `_keywords` 조사 미제거 | **고침** | 빈출 조사·어미를 떼어 어간 비교. `_STEM_MIN=2`로 '주문'이 '주'가 되지 않게 막았다 |
| B-3 `probe_profiles` 순차 실행 | **고침** | `asyncio.gather`로 병렬화. 0.3초짜리 서버에서 1.18초 → 0.56초 |
| B-4 A/B·회전 콘텐츠 오탐 | **고침** | 같은 프로필 재요청으로 **자기 유사도**를 먼저 재고, 프로필 간 차이가 그 잡음보다 뚜렷할 때만 판정. 잡음이 85% 아래면 판정을 포기하고 사유를 남긴다 |
| B-5 MIS-BUSINESS-IDENTITY 무조건 | **고침** | 거래 유도 또는 개인정보 수집이 있을 때만 판정. 정보성 랜딩은 제외 |
| B-6 응답 전체 다운로드 | **이미 해결** | A-1과 같은 커밋에서 스트리밍 절단 |
| B-7 공개 배포 시 오픈 프록시 | **미해결 (의도)** | 로컬 실행 도구이고 배포 계획이 없다. 공개 배포한다면 rate limit·API 키가 선행되어야 한다 |
| B-8 동기 DNS로 루프 블로킹 | **고침** | `assert_safe_url_async`로 이름 풀이를 스레드에 넘긴다. 병렬 수집(B-3)과 함께여야 의미가 있다 |

## C. 기능 공백

| 항목 | 상태 |
|---|---|
| C-1 전후 비교·이력 | **이미 해결** — `history.py` JSONL 장부 + `GET /v1/history` + 화면의 "지난 점검과 비교" |
| C-3 제한 업종 카탈로그 | **부분** — 암호화폐·데이팅·주류·부정행위 조장·위험 제품이 추가됐다. 담배 단독, 대부업 고지, 구인구직은 아직 없다 |
| C-7 TikTok | **부분 → 언어 일치 추가** — `TT-LANGUAGE-MISMATCH`. TikTok은 광고 문구와 랜딩페이지가 둘 다 타겟 지역 허용 언어와 맞아야 한다고 요구한다. 타겟 지역을 모르므로 **둘이 서로 다르다는 사실만** 알린다. 남은 것: TikTok 금지 업종, 랜딩 완성도 |
| C-2 광고 문구 편집 요건 | **해결** — `adcopy.py`. 제목·설명 글자 수(**한국어는 문자 하나가 두 자 → 실질 15자/45자**), 문장부호 반복, 장식 기호·이모지, 대문자 남용, 불필요한 반복, 자간 벌리기. 화면에는 타이핑하는 동안 글자 수가 바로 보인다. "여기를 클릭"은 **넣지 않았다** — 편집 기준 문서(한국어·영문)에 그런 조항이 없다 |
| C-4 배치 검사 | **미해결** — 대행사 시나리오에는 필요하다 |
| C-5 오탐 무시(ignore_codes) | **해결** — 요청의 `ignore_codes`로 점수·판정에서 빼고 `suppressed`로 따로 돌려준다. 계정 정지·경고 누적급과 없는 코드는 422. 이력에는 무시한 코드까지 적어 '해결됨'으로 오인되지 않는다. 화면에서 카드마다 무시/해제, 목록은 브라우저에 저장. MCP에는 노출하지 않는다 |
| C-6 모바일 스냅샷 미활용 | **해결** — 모바일 스냅샷에도 룰셋을 돌리고 `[모바일]` 표시를 붙인다. 데스크톱에서 이미 나온 코드는 중복으로 올리지 않는다. 추가 요청 0회 |
| C-8 evidence 위치 정보 | **해결** — `locate.py`. 근거를 스냅샷 필드(제목·메타·링크·alt·폼·본문·이미지 글자)와 광고 필드(제목·설명·문구)에서 다시 찾아 `locations`로 붙인다. 역검증과 같은 정규화, 이어 붙인 근거는 조각별, 모바일 전용은 `mobile:`. 설명형 근거는 비워 둔다. 화면·MCP 응답에도 실린다 |

## 반영 중 발견한 것 (리뷰에는 없던 문제)

`difflib.SequenceMatcher`의 기본값 `autojunk=True`가 **유사도 판정을 망가뜨리고 있었다.**
200자가 넘는 쪽에서 1% 넘게 나오는 요소를 잡음으로 빼는 최적화인데, 상품 목록·후기처럼
같은 구조가 반복되는 페이지는 거의 모든 글자가 그 조건에 걸린다.

```
같은 문장 20번 반복 + 일부만 다른 두 페이지
  autojunk=True (고치기 전)   유사도 0.02  →  [block] ABUSE-CLOAKING (계정 정지급)
  autojunk=False (고친 뒤)    유사도 0.58  →  지적 없음
```

반복 구조가 있는 정상 쇼핑몰이 계정 정지급으로 보고되던 상황이다. 이 도구에서 나올 수
있는 가장 나쁜 종류의 오탐이라 즉시 고쳤다.
