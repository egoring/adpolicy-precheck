## A. 버그·보안 (높음)

### A-1. SSRF 방어의 리디렉션 우회 구멍
- **위치**: `api/src/adpolicy/fetcher.py` `fetch()`, `cloaking.py` `probe_profiles()`
- **문제**: `assert_safe_url()`은 **최초 URL만** 검사하는데 두 곳 모두 `follow_redirects=True`.
  공개 URL이 `http://192.168.x.x`, `http://169.254.169.254`(클라우드 메타데이터) 등으로 302 리디렉션하면 그대로 따라간다.
  추가로 검사 시 DNS 1회, httpx 요청 시 재해석 1회 → TOCTOU(DNS 리바인딩) 여지.
- **수정 방향**: httpx event hook(`response` 훅에서 redirect 대상 재검증) 또는 `follow_redirects=False`로 직접 루프를 돌며 매 hop마다 `assert_safe_url` 재호출. 리바인딩까지 막으려면 검증한 IP로 직접 연결하는 custom transport.

### A-2. CI가 push에서 영원히 안 돎
- **위치**: `.github/workflows/ci.yml` ↔ `.git/HEAD`
- **문제**: 저장소 브랜치는 `master`(HEAD: `ref: refs/heads/master` 확인)인데 워크플로는 `push: branches: [main]`. push CI가 한 번도 안 돌고 README 배지도 빈 상태가 된다. `[재현 확인 — git 메타데이터]`
- **수정 방향**: 브랜치를 `main`으로 개명하거나 워크플로에 `master` 추가. 둘 중 하나로 통일.

### A-3. web Docker 빌드 실패 가능성 + lockfile 미사용
- **위치**: `web/Dockerfile`, `.github/workflows/ci.yml`
- **문제 1**: deps 스테이지가 `npm install --omit=dev` → typescript·@types 없는 node_modules를 builder가 물려받아 `next build` 실행. tsconfig가 있는 TS 프로젝트에서 Next 14는 typescript 부재 시 빌드 중단. (네트워크 차단으로 직접 빌드 확증은 못 함 — `docker compose build web`으로 확인 필요)
- **문제 2**: `COPY package.json ./`만 있어 커밋된 `package-lock.json`이 Docker에서 안 쓰이고, CI도 `npm install` 사용 → 재현 가능한 빌드가 아님.
- **수정 방향**: deps 스테이지에서 lockfile 포함 `COPY package.json package-lock.json ./` + `npm ci`(dev 포함), runner에는 standalone 산출물만 가므로 이미지 크기 영향 없음. CI도 `npm ci`.

### A-4. `ABUSE-UA-BRANCHING` — 거의 모든 실사이트에서 오탐 `[재현 확인]`
- **위치**: `cloaking.py` `UA_SNIFF_PATTERNS`, `main.py` `run_cloaking_checks()`
- **문제**: `navigator.userAgent`는 GA/gtag·모바일 감지 등 평범한 스크립트에 다 들어 있다. GA 스니펫 하나로 warn 발생을 재현함. "오탐이 몇 번 나면 도구 전체를 믿지 않는다"는 설계 원칙(설계서 4-3)에 정면 충돌.
- **수정 방향**: 신호를 좁히거나(UA 검사 + `location.replace`/`document.write` 등 콘텐츠 변경 조합일 때만) severity를 info로 하향. 또는 프로필 간 실제 분기가 관측될 때만 보조 근거로 승격.

### A-5. `DEST-MISMATCH` — www 리디렉션 오탐 `[재현 확인]`
- **위치**: `rules.py` `check_technical()`
- **문제**: netloc 단순 비교라 `example.com → www.example.com`(매우 흔한 정상 구성)이 warn.
- **수정 방향**: 등록 도메인(eTLD+1) 기준 비교. 간단히는 `www.` 접두사 정규화 + 포트 제거부터.

### A-6. "봇에게만 빈 200 응답(JS 셸)" 미탐 `[재현 확인]`
- **위치**: `cloaking.py` `analyze_divergence()` `MIN_TEXT_FOR_COMPARISON`
- **문제**: README가 잡는다고 명시한 시나리오("JS 전용 렌더링이라 크롤러에는 빈 페이지")인데, 봇이 200 + 거의 빈 HTML을 받으면 본문 200자 미만이라 비교 대상에서 **제외**되어 판정 없이 통과. 봇이 에러일 때만 잡힌다.
- **수정 방향**: "다른 프로필은 길고 특정 프로필만 짧다"를 그 자체로 분기 신호로 처리 (예: 최대 길이 대비 일정 비율 미만이면 warn/block).

### A-7. 봇 프로필 일시 타임아웃 → 즉시 block
- **위치**: `cloaking.py` `analyze_divergence()`, `probe_profiles()`
- **문제**: 순간 네트워크 장애로 bot 요청 하나만 실패해도 재시도 없이 `ABUSE-CLOAKING` block. 오탐 비용이 큰 판정을 단일 시도로 확정한다.
- **부수**: `test_single_usable_profile_yields_no_verdict`는 이름은 "no verdict"인데 assert는 `"block"` — 테스트 이름과 동작 불일치.
- **수정 방향**: 봇 실패 시 1회 재시도 후 판정. 타임아웃(불확실)과 4xx(명시적 거부)의 severity 구분도 고려. 테스트 이름 정정.

## B. 정확도·성능 (중간)

### B-1. robots.txt 파서의 한계 `[재현 확인]`
- **위치**: `cloaking.py` `check_robots()`
- 경로 단위 `Disallow: /landing`이 실제 랜딩 URL을 막아도 `/`만 인정하므로 **미탐**.
- `AD_CRAWLERS`에 `googlebot` 포함 — 유기적 Googlebot 차단은 광고 심사(AdsBot)와 무관한데 같은 `DEST-NOT-CRAWLABLE`로 잡혀 **오탐** 소지.
- 그룹형 레코드(User-agent 여러 줄 연속 + Disallow)에서 마지막 UA만 남는 파싱.
- **수정 방향**: stdlib `urllib.robotparser`로 대상 URL 경로에 대한 `can_fetch("AdsBot-Google", url)` 판정 + "AdsBot은 전역 `*`를 따르지 않는다" 규칙만 커스텀 유지. googlebot은 목록에서 제거하거나 별도 info 항목으로 분리.

### B-2. `_keywords`가 조사를 안 떼어냄 `[재현 확인]`
- **위치**: `rules.py` `_keywords()` / `check_ad_page_match()`
- **문제**: 주석은 "조사를 털어낸다"지만 `[가-힣]{2,}`는 "원두를", "배송을"을 통째로 토큰화. 정상 관련 광고/페이지 쌍에서 키워드 6개 중 4개가 조사·어미 때문에 미매칭(ratio 0.33, 경계 0.3 바로 위)을 재현 — 활용형이 조금만 많아지면 `MIS-UNCLEAR-RELEVANCE` 오탐.
- **수정 방향**: 빈출 조사(을/를/이/가/은/는/의/에/로/에서/까지…) 접미 제거, 또는 부분 문자열 매칭(앞 2~3글자 stem 매칭)으로 완화.

### B-3. `probe_profiles` 순차 실행
- **위치**: `cloaking.py` `probe_profiles()`, `main.py`
- **문제**: README·주석은 "동시에 가져온다"인데 실제로는 프로필 3개를 for 루프 순차 요청. 응답 시간 3배, robots 확인도 직렬.
- **수정 방향**: `asyncio.gather`로 프로필 병렬화 + robots 동시 실행. 문서와 일치하게 됨.

### B-4. A/B 테스트·회전 콘텐츠에 의한 클로킹 오탐 여지
- **문제**: 요청마다 콘텐츠가 바뀌는 사이트는 클로킹 없이도 프로필 간 유사도가 낮아진다.
- **수정 방향**: 같은 프로필(desktop) 2회 요청으로 "자기 유사도" 기준선을 재고, 프로필 간 유사도가 기준선보다 유의하게 낮을 때만 판정.

### B-5. `MIS-BUSINESS-IDENTITY` 무조건 판정
- **위치**: `rules.py` `check_absence()`
- **문제**: 가격·개인정보방침은 조건부 판정으로 설계해 놓고 이것만 모든 페이지에 무조건 적용 — 블로그형 랜딩에서 오탐.
- **수정 방향**: 상거래 의도(COMMERCE_INTENT)나 폼 존재 등 조건과 결합.

### B-6. 응답 전체 다운로드 후 절단
- **위치**: `fetcher.py`·`cloaking.py`의 `resp.content[:MAX_BYTES]`
- **문제**: 3MB 제한이 다운로드 제한이 아니라 사후 잘라내기 — 대용량 응답이 메모리를 전부 차지.
- **수정 방향**: `client.stream()`으로 받다가 MAX_BYTES에서 중단.

### B-7. 공개 배포 시 오픈 프록시화
- **문제**: 인증·rate limit 없음. 체크 1회당 외부 사이트에 4회(3프로필 + robots) 요청 — 공개로 띄우면 제3자 사이트를 두들기는 프록시로 악용 가능.
- **수정 방향**: 배포 전 rate limit(slowapi 등)·API 키. README에 배포 주의사항 한 단락.

### B-8. 동기 DNS 호출로 이벤트 루프 블로킹
- **위치**: `fetcher.py` `assert_safe_url()`의 `socket.getaddrinfo`
- **수정 방향**: `loop.getaddrinfo()`(비동기) 사용.

## C. 기능 공백

### C-1. 수정 전후 비교·검사 이력 없음 ★ 자기모순
- 설계서 4-4가 "사용자는 수정 전후를 비교하려고 점수를 본다"를 결정적 점수의 근거로 드는데, 비교 기능 자체가 없다. 이력 저장 없음, 재검사 버튼 없음, 이전 결과와의 diff("해결됨 1건 / 신규 0건 / 잔여 2건") 없음.
- **방향**: 최소 구현은 SQLite(또는 JSON 파일)에 (url, ad_copy 해시, findings, score, 시각) 저장 + `GET /v1/history?url=` + 웹 UI에서 직전 결과와 코드 단위 diff 표시.

### C-2. 광고 문구 편집 요건 검사 부재 ★ 비용 대비 효과 최대
- Google Ads 최다 반려 축인 편집 기준(answer/6021546)이 전무: 제목 30자·설명 90자 초과, 느낌표·물음표 반복("!!"), 기호 남용(★♥), 이모지·전각 문자, 과도한 대문자, "여기를 클릭" 류 일반 문구.
- 전부 정규식으로 100% 결정적으로 판정 가능 → 이 프로젝트의 룰셋 계층에 정확히 부합. `ad_copy`를 headline/description 구조로 받는 입력 확장도 함께 고려.

### C-3. 제한 업종 카탈로그가 5개뿐
- 현재: healthcare, financial, gambling, sexual, counterfeit.
- 누락: 주류, 담배·전자담배, 암호화폐, 다이어트·보조제, 대출·대부(국내 필수 고지 의무), 성형·시술, 구인구직, 부동산, 정치광고 등. `PolicyItem` 구조가 잘 되어 있어 추가 비용은 낮다.

### C-4. 배치 검사·비동기 job 없음
- 대행사 시나리오(문서가 상정하는 사용자)는 캠페인 단위 수십 건 검사가 기본인데 단건 동기 POST뿐. LLM 포함 시 요청 하나가 최대 120초를 점유.
- **방향**: `POST /v1/batch`(URL×문구 목록) + job id 폴링(또는 웹훅). UI에 CSV 업로드·표 결과.

### C-5. 오탐 무시(suppression) 기능 없음
- 근거 있는 "업계 1위" 광고주는 매번 `MIS-SUPERLATIVE`를 본다. 요청 단위 `ignore_codes` 파라미터나 프로젝트 단위 억제 목록이 없어 오탐 하나가 영구적으로 점수를 깎는다. C-1과 결합하면 "해결/무시/신규" 구분이 가능해진다.

### C-6. 모바일 스냅샷을 받아놓고 안 씀 ★
- `probe_profiles`가 mobile 프로필 페이지를 이미 가져오지만 클로킹 유사도에만 사용. 룰셋·LLM 분석은 desktop 스냅샷만 대상 — m.도메인/모바일 전용 랜딩의 위반(가격 없음, 방침 없음)이 통과한다.
- **방향**: 룰셋을 프로필별로 실행하고 finding에 프로필 표기. 추가 네트워크 비용 0.

### C-7. TikTok은 사실상 이름만 존재
- 플랫폼 enum + `TT-BEFORE-AFTER` 1건이 전부. TikTok 고유 정책(광고↔랜딩 **언어 일치** 요건, 랜딩 완성도, TikTok 금지 업종) 미구현이고 출처 URL도 없음. 언어 일치 검사는 언어 감지만으로 결정적 구현 가능.

### C-8. evidence 위치 정보 없음
- "100% 보장"이 제목인지 본문인지 링크 텍스트인지 alt인지 알려주지 않음(combined_text로 합쳐 검증하는 구조). 스냅샷이 필드별로 분리돼 있으므로 어느 필드에서 매칭됐는지만 붙여도 수정 UX가 크게 개선.

### C-9. 그 외
- 페이지 내 주요 링크 404(깨진 링크) 검사 없음 — destination 요건 해당.
- 결과 공유·내보내기(PDF·공유 링크) 없음 — 대행사→클라이언트 전달 시나리오.
- CI 파이프라인용 CLI 없음(exit code로 fail 판정) — `check.sh`는 이 역할 불가.
- 집행 중 광고의 사후 모니터링(정기 재검사 + 랜딩 다운 알림) 없음.
- 점수 산식 분해(finding별 감점 내역) 미노출 — stats에 breakdown 추가 고려.
